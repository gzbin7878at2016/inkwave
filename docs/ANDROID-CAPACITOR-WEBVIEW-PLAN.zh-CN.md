## 1. 可行性结论与范围

**可行，适合先做 Android 验证版。** 保留现有 Three.js、玩法与联机架构，以 Capacitor 创建 Android 外壳，在系统 WebView 中加载 APK 内置网页资源。壳工程只是入口；真正的工作量集中在 **触屏手感、持续性能、手机联机稳定性**。

能看到画面不等于能完成一局；冷机帧数不等于热机稳定；WebSocket 连上不等于切网、锁屏或房主退出后仍正确。第 04、07、11、15 步分别设关卡，任何关卡失败都应先解决阻塞，不靠降低验收口径宣布完成。

首版交付范围：横屏 Android APK；离线完整对局；手机触屏全操作；保留桌面键鼠与手柄；使用明确配置的 WSS 中继联机；掉线可解释、房主迁移不产生两个权威。首版不承诺断网后原身份无缝回到正在进行的对局，不承诺后台持续运行比赛，不含 iOS、原生引擎重写、账户系统、支付、语音和热更新。

如果第 11 步在指定中端机上，最低可接受画质仍达不到稳定 30 FPS，应暂停扩机和发行：先定位 CPU、GPU、显存、热降频瓶颈；再决定减少效果/装饰或另评估原生方案，不能假定换壳能提升 WebGL 性能。

### 1.1 目标设备与能力门槛

- 产品首轮测试建议从 Android 10+ 开始，至少覆盖一台 Adreno 和一台 Mali GPU；这是项目测试范围建议，不是 Capacitor 自身最低支持版本。
- Capacitor 官方 Android 页面当前列出 API 24+ 支持；游戏实际还依赖 WebGL2、ES Modules/import map 和所用渲染目标格式，不能据此承诺所有 Android 7 手机可玩。[Capacitor Android](https://capacitorjs.com/docs/android)
- 应启动时实测 WebGL2、必要扩展与渲染目标完整性，失败显示具体能力原因和更新 WebView 的指引，不无限黑屏。当前 Three.js WebGLRenderer 面向 WebGL2；以仓库实际 vendor 版本为准，避免把 npm 声明版本当作已运行版本。[Three.js WebGLRenderer](https://threejs.org/docs/pages/WebGLRenderer.html)
- 模拟器用于安装、页面和生命周期冒烟；性能与操作最终必须由真实手机验收。记录 Android 版本、WebView 提供方/版本、GPU、刷新率、可用内存、屏幕分辨率及 APK 构建号。

## 3. 目标结构与固定实施决策

```text
Android Activity / Capacitor 原生层
  ├─ 生命周期、返回键、横屏/安全区域、可选热状态桥接
  └─ 系统 WebView，加载 APK 内置 dist-mobile/index.html
       ├─ Three.js / 玩法 / Web Audio
       ├─ TouchInput → Input 动作快照 → PlayerController → Actor intent
       ├─ 移动 HUD / 地图 / 技能光标
       ├─ 移动性能档 + 单一动态分辨率控制器
       └─ Transport / Session / NetMatch → 指定 WSS 中继
```

1. 使用仓库根作为 npm 项目，新增 Capacitor 配置与 `android/`；原有 Electron 命令保留。
2. 首次实施选择执行当天可获得的 Capacitor 8 稳定版精确版本，core/android/cli 保持相同版本，官方插件按兼容关系分别锁版；写入 lockfile，后续不自动升级。环境基线以官方当前要求复核；当前文档列 Node.js 22+、Android Studio 2025.2.1+。[环境要求](https://capacitorjs.com/docs/getting-started/environment-setup)
3. 固定新增 `tools/build-mobile.mjs`，负责用精确锁版的 esbuild 打包入口和复制静态资产，输出 `dist-mobile/`；不替换旧 build，不改变现有 dist。构建器不可只复制带 `@capacitor/*` 裸导入的源码。
4. 产物 `index.html` 移除 import map，模块入口指向打包后的 JS；构建入口使用仓库 vendor 的 Three.js，而非悄悄切换到另一个 npm three 副本。保留 vendor addons 对 core 的一致引用。
5. `assets/`、`styles/` 保持相对目录；盘点 `new URL(..., import.meta.url)`、动态 import、Worker、字体和音频路径，按资源逐项处理。禁止仅因首页成功就认定所有地图/武器资源有效。
6. 发布资源必须内置；开发临时 `server.url` 不进入 release。Capacitor 配置说明将远端 URL 用于开发热重载，不作为本方案生产加载方式。[配置参考](https://capacitorjs.com/docs/config)
7. 壳的本地域名/协议首次验证后保持稳定，避免 localStorage 源变化丢设置。开发页面、桌面 Electron 与 APK 的存储不会自动互相迁移。
8. 原生插件通过将来的 `src/platform/mobile.js` 统一封装，桌面调用安全回退；不在渲染热循环每帧跨原生桥传数据。
9. 不默认开启原生 HTTP 代理插件；浏览器 WebSocket 仍使用网页网络栈，不会因为启用 HTTP 插件就自动解决 WSS、证书或断线续局。

建议配置骨架（第 04 步确认应用 ID 无冲突后写入；本段只是方案示例）：

```json
{
  "appId": "com.demoink.inkwave",
  "appName": "INKWAVE",
  "webDir": "dist-mobile",
  "server": { "hostname": "localhost", "androidScheme": "https" }
}
```

`webDir` 指向网页构建产物，不指向项目根、src 或 android。更新流程固定为：生成网页 → `npx cap sync android` → 构建安装；sync 本身不替代网页构建。[开发工作流](https://capacitorjs.com/docs/basics/workflow)

## 5. 十六步执行计划

每步工时均是有项目经验的执行者在 AI 辅助下的有效工时范围，不是 AI 连续生成代码的墙钟时间。下载、跨设备等待、测试者反馈、商店审核另计。第 06、07、10～14 步需人工判断或多设备，不能全交给 AI 自证。

### 第 01 步：冻结基线与列验证清单（4～6 小时）

**前置**：读完本文；能访问现有仓库。**允许范围**：进度文档与基线测试清单，不改玩法。

**如何做**：
1. 记录 HEAD、分支、远端与工作树，确认用户代码未被覆盖；建立工作分支。
2. 读取第 2 节文件，列出桌面现有输入动作、所有模式、地图、武器和特殊技能操作。
3. 运行 `npm run check`；若依赖未安装，按 lockfile 安装并记录，不全局升级。离线网页完成一局并记录当前已有错误。
4. 记录 vendor Three.js 实际版本、资产体积和最重地图候选；建立三台测试机清单，至少两种 GPU。

**验收**：基线 commit、自动检查、完整一局基线和设备矩阵可追溯；已有缺陷与移动改动区分。
**注意**：把“可运行基线”作为对比，不用前一轮仅注释检查代替真实游戏验证。
**Kimi 本步任务**：只完成基线盘点，创建进度/设备/操作矩阵；不要装壳或重写输入。

### 第 02 步：准备 Android 工具链并锁版（6～10 小时）

**前置**：01 完成。**允许范围**：npm 依赖、锁文件、环境记录和忽略规则。

**如何做**：
1. 核对 Node、npm、Python、Android Studio、SDK、adb 和 Studio 使用的 JDK；Gradle 用工程 wrapper，不用随意安装的全局版本。
2. 查当天 Capacitor 8 稳定版本，记录精确版本。用 `npm install --save-exact 包名@已核实版本` 安装 core/android；用 `--save-dev --save-exact` 安装 cli/esbuild；后续需要的 App、Network、ScreenOrientation 插件也分别查兼容版本后锁定。
3. Android Studio 安装生成工程要求的 compile SDK、build tools 和 platform tools；minSdk、targetSdk 与 compileSdk 分别记录，不能因官方支持 API 24 就把 compileSdk 设为 24。
4. adb 识别真机并完成 USB 调试授权；记录 WebView 版本。Gradle/npm 下载代理分别检查，不通过关闭 TLS 校验绕过下载失败。
5. 忽略 dist-mobile、android 的构建/本机配置及签名私密文件；保留 wrapper 与平台源码。

**验收**：精确锁版清单和工具版本齐全；真机可由 adb 访问；不会把本机路径提交。
**注意**：应用商店 target API、签名要求在发行时另查官方当期规则，不把当前建议当永久要求。
**Kimi 本步任务**：只准备环境与依赖；下载失败报告来源和错误，不升级整个项目。

### 第 03 步：建立独立移动网页构建（6～10 小时）

**前置**：02 完成。**允许范围**：新增 build-mobile、移动入口/配置、npm 脚本与必要资产路径修正。

**如何做**：
1. 新建 `tools/build-mobile.mjs`，通过固定项目根定位源码，以 esbuild 打包 `src/main.js` 或薄包装移动入口。将 `three`、`three/addons/` 精确解析到现有 vendor；不同时打入两个 Three.js。
2. 输出 dist-mobile，复制 assets/styles；按实际引用处理 songs/manifest 可选缺失，首版不要求读取任意外部存储音乐。
3. 遍历所有动态 import 与 `new URL(..., import.meta.url)`：对 AO、字体、音频、纹理逐项确认产物路径。打包后的 import.meta.url 已不一定在原 src 目录，不能盲目复制源码相对表达式。
4. 生成产物 index.html，保留挂载节点与 CSS，去除源 import map，入口改为产物 JS。网页 CSS 与 js 命名固定或同步替换，不残留失效 src 路径。
5. npm 新增 `build:mobile`。脚本仅清理解析验证后位于仓库内的 dist-mobile；不得清理 docs、android 或旧 dist。
6. 用本地 HTTP 服务仅服务 dist-mobile，关闭外网后走所有菜单与地图；控制台不得出现无法解析 `@capacitor/*`、资源 404 或重复 Three 实例类型错误。

**验收**：产物独立可运行；一次完整离线比赛通过；资源清单与构建结果可重现；旧网页/Electron 路径仍可使用。
**注意**：不要直接把 core 插件 import 写入旧原生 ESM 页面却不提供构建或解析方式；桌面入口也需做兼容验证。
**Kimi 本步任务**：实现移动构建，提交构建脚本和配置；不提交 dist-mobile 生成文件。

### 第 04 步：生成外壳并完成能力验证（6～10 小时）

**前置**：03 完成；应用 ID 无已有冲突。**允许范围**：Capacitor 配置、android 工程和启动能力页。

**如何做**：
1. 初始化上述配置，执行 `npx cap add android`（只在 android 不存在时执行）。重复实施使用已有工程，不重新覆盖。
2. 执行 `npm run build:mobile`、`npx cap sync android`、`npx cap open android`。官方流程要求先构建再同步，sync 不会编译游戏 JS。
3. 构建 debug APK，adb 安装；在有权调试的 debug WebView 中用 Chrome DevTools 查看控制台、网络、WebGL2 和 framebuffer 完整性。确认 app 层 INTERNET 权限、硬件加速和页面实际源。
4. 冷启动 10 次，逐次切不同地图；检查离线启动资产，缺能力给出可读提示。记录当前设备 WebView，而非只报 Android 版本。
5. 关闭电脑网页服务器，再启动 APK；应仍能进入离线菜单与比赛。

**验收关卡 A**：真实 APK 可脱离电脑服务启动，场景和基本音效正常；渲染目标通过能力测试，无黑屏和资源 404。
**注意**：此时可能还不可触控，不算可玩交付；不使用 file:// 或 release server.url 偷换本地资源方案。
**Kimi 本步任务**：完成壳与能力日志；缺手机则停在可构建，明确关卡 A 未验收。

### 第 05 步：接生命周期、返回键与横屏（8～14 小时）

**前置**：04 通过。**允许范围**：新增 platform/mobile、main 生命周期入口、Android 窗口配置。

**如何做**：
1. 平台适配模块封装 App 状态、返回键、横屏和网络变化；初始化一次，销毁时解绑；浏览器入口安全回退。
2. 首版采用固定横屏。系统栏、安全区与 viewport resize 都触发一次布局更新，不能同时拉起两个 RAF 循环。横屏锁使用原生配置/兼容插件，不把网页 Screen Orientation 支持当保证。
3. 后台时清空全部触控、按键边沿、蓄力、开火；离线暂停，音乐/音效暂停；恢复后显示“继续”，需用户点击再恢复音频和游戏输入。
4. 联机后台不暂停整个房间，也不把长时间后台间隔作为一个超大 dt 补算；先禁本地输入，恢复走第 13 步的会话验证。
5. 返回键层级：有文本编辑先收键盘；再关二级弹层；比赛中打开暂停/离开面板；顶层大厅退出需确认，不能一按就杀进程。
6. 覆盖切后台、锁屏、来电/通知面板、恢复和 Activity 重建。用实例标识检查事件监听、RAF 和音频节点没有重复。

**验收**：每种切换 10 次无粘键、重复循环、爆音、无限暂停；桌面失锁暂停规则不受影响。
**注意**：生命周期和 backButton 由插件提供接口，监听返回键后要明确处理自己的导航语义。[App 插件](https://capacitorjs.com/docs/apis/app)；[横屏插件](https://capacitorjs.com/docs/apis/screen-orientation)
**Kimi 本步任务**：只接生命周期和返回层级；先不实现自动续局。

### 第 06 步：实现真正多指 TouchInput（12～20 小时）

**前置**：05 完成。**允许范围**：新增 `src/core/touchInput.js`、触控 HUD/CSS、Input 扩展，不改伤害判定。

**如何做**：
1. 采用 Pointer Events，维护 `Map<pointerId, role>`，role 为 move/look/button/map；按下时确定归属，直到结束不因拖过另一个区域就改归属。
2. 左区摇杆、右区滑动瞄准、独立动作按钮各持自己的指针；获取 pointer capture；处理 up、cancel、lostpointercapture、blur 和后台的统一清空。
3. 游戏区域 `touch-action:none`，文本/菜单滚动区域保留本身行为。阻止浏览器手势与合成鼠标重复触发，不能禁掉所有菜单输入。
4. 触控状态分 held、pressed、released、move vector、look delta；endFrame 仅清边沿和增量，不清仍按住的按钮。
5. 多指同时移动+转视角+开火+跳跃；手指离开按钮范围、系统抢手势、指针复用都需验证。
6. 调试面板可显示 pointerId/role/held/边沿计数；release 构建隐藏，不逐帧 console.log。

**验收**：100 轮随机按下/抬起/取消后所有指针归零；至少四指并行不会抢角色、卡火或抖动切区。
**注意**：Pointer Events 的 pointer capture 与 touch-action 是明确的网页输入机制；实际系统抢占仍须真机验证。[Pointer Events](https://developer.mozilla.org/en-US/docs/Web/API/Pointer_events)
**Kimi 本步任务**：实现并验证输入采集；输出事件序列检查，不直接从按钮调用武器开火函数。

### 第 07 步：接控制器并调触屏手感（12～20 小时）

**前置**：06 完成。**允许范围**：Input、PlayerController、主循环输入门控、触控设置。

**如何做**：
1. 定义统一动作快照，桌面和触控都映射到现有 intent；新增 lastDevice='touch'，按能力/平台决定启用，不只用 UA 字符串。
2. 移动端 play/resume 不等 pointer lock 成功；_onPointerUnlock 只对实际锁定过的键鼠模式生效。键鼠连接手机仍应可切设备，不全局删除锁定代码。
3. 左摇杆半径初值 64 CSS px、死区 0.12、圆形归一化、饱和 1；允许半径 48～96 px。角色移动速度继续用现有物理，不因换触控而提高。
4. 右区默认相对拖动瞄准：每帧累加指针位移，yaw 初值 0.005 rad/CSS px、pitch 初值 0.004；增量不再乘 dt，不乘 DPR。可选固定摇杆模式则使用 rad/s×dt，不能混用两种单位。
5. 默认关闭额外瞄准平滑，先观察原始响应；必要时用时间常数不超过约 15ms 的单层低通。先只沿用已定义的 pitch 限幅；辅助瞄准独立开关，不能暗中提高命中率掩盖触控问题。
6. 开火/潜墨按住；跳跃按下沿；副武器同时保留按住瞄准/松开投掷；大招按下沿；地图打开屏蔽普通射击；取消操作显式可达。
7. 测试射手、蓄力武器、弓、伞、摇罐、回旋镖等不同 hold/release 行为；避免松手边沿因帧节流丢失。30/60Hz 下同样输入距离，转角和移动量应一致。
8. 至少 3 位使用者各做 10 分钟：走八字、移动跟枪、180°转身、边跳边射、潜墨爬墙、抛副武器；记录滑过头、误触和疲劳，调整一项参数后重复，不一次混改所有参数。

**验收关卡 B**：不用实体键盘能完整打一局并操作所有首版动作；4 指组合无冲突；三位使用者报告与参数表入档。可用高速摄影估计触到画面的端到端延迟；JS 事件时间只能证明局部耗时，不冒充整链延迟。
**注意**：上述数值是可重复调试起点，不是已验证最佳手感；优先减少延迟，再讨论加速曲线。
**Kimi 本步任务**：按动作表接控制器，提供参数设置与测试记录模板；触屏手感必须留给人确认。

### 第 08 步：HUD、地图与特殊技能可操作化（8～14 小时）

1. 横屏按钮以安全区内的 CSS px 布局，点击目标至少 48×48 px；不能按设备物理像素写死。视角区避让按钮指针，保留中央视野。

### 第 10 步：建立移动画质与性能测量（14～24 小时）

**前置**：可触屏完整比赛。**允许范围**：config 移动默认值、renderer、main 动态分辨率、性能面板。

**如何做**：
1. 先记录基线 frame interval、CPU update/render 提交耗时、draw calls、三角数、分辨率、renderer.info 几何/纹理数量；CPU render 调用时间不等于 GPU 完成时间。
2. 手机新档案默认 low 起步：沿用 DPR cap=0.75、AO/bloom/MSAA 关闭、paintAtlas=2048、particles=0.4、shadowSize=1024 的已有低档契约。是否关闭阴影另测，不改所有平台默认 high。
3. 手机高档仅在通过设备实测后开放；分辨率计算只保留一个最终控制入口，避免已有 dynScale 与新增移动缩放相乘后不可解释。
4. 第一次实施先固定 30 FPS 可持续目标，再给达标设备提供 60 FPS；目标帧节流使用 RAF 时间戳，输入事件继续收集。模拟用实际受控 dt/子步，不把游戏速度随渲染帧率改变。
5. 每秒聚合指标，10 秒输出一行数据；提供关闭性能 HUD 的方式，测量开关对比确保观测开销可接受。
6. 单变量测试：分辨率 → 阴影 → 后处理 → 粒子 → 装饰/角色 → Bot。降分辨率明显改善偏 GPU，分辨率变化不改善而 update 耗时高时优先查 CPU。
7. 动态分辨率初始边界设移动 low 基础比例的 0.75～1，每次改 0.05；持续 3 秒超帧预算才降，低于预算 15% 持续 15 秒才升，每 5 秒最多变一次。参数记日志，再按真机调整，保留手动固定档供对比。
8. 不运行时反复调整墨图集尺寸；切图集等重建放在菜单/重载流程。状态展示注明当前档、最终像素尺寸与降档原因。

**验收**：同场景可导出可比数据；30/60 目标不会改变移动、蓄力或网络时钟；DPR 没有被设备 3～4 倍像素密度放大。
**注意**：支持时用 disjoint timer query 辅助 GPU 计时，读取异步结果并检查 disjoint；不每帧 readPixels/getError/gl.finish 强制同步。WebGL 内存与调用实践参考 [WebGL 性能建议](https://developer.mozilla.org/en-US/docs/Web/API/WebGL_API/WebGL_best_practices)。
**Kimi 本步任务**：实现可测量低档与单一缩放控制器；先交原始数据再调参，不凭看起来顺畅填指标。

### 第 11 步：热机、显存与长时间稳定性（10～18 小时）

**前置**：10 完成。**允许范围**：性能瓶颈修复、资源释放、上下文丢失恢复与统计。

**如何做**：
1. 三台机每台固定场景运行 30 分钟，记录 0～5、10～15、25～30 分钟窗口。室温记录约 23～27°C、不充电、亮度固定、相同保护壳状态，每组重跑前冷却到相近起点。
2. 最重地图分别跑 4v4、大招爆发、地图俯视和 Boss+小蟹；先找最大值场景，再对其他地图每张至少完整一局。
3. Android logcat/系统 tracing 查卡顿和内存压力；`adb shell dumpsys meminfo com.demoink.inkwave` 的进程数据与 renderer.info 计数联合看，不能把纹理个数直接当显存 MB。
4. 反复入局/退局/切地图 20 次，检查材质、纹理、几何、音频和事件数量是否回归平台；记录暖缓存后趋势，缓存稳定持有不简单等同泄漏。
5. 捕获 webglcontextlost 时停止依赖 GL 的绘制并显示恢复提示；优先验证渲染器/游戏可否完整重建，恢复失败受控重载。联机重载默认视为掉线，不伪造保局。
6. 热状态若需原生桥接，低频事件驱动，不每帧轮询。Android Thermal API 只在支持的版本/设备读取；缺失时以帧时间保底，不拿电池温度冒充 GPU 温度。[Thermal API](https://developer.android.com/games/optimize/adpf/thermal)
7. 所有优化不能按手机各自删 Bot、减少比赛伤害采样、改变地图实体或地雷规则；可独立减少纯视觉粒子、阴影更新及远处装饰。

**验收关卡 C（暂定产品目标，尚未测过）**：中端目标机最后 5 分钟 30 FPS 档中位帧率≥29、P95 帧间隔≤40ms，>100ms 长帧≤3 次/分钟；高档 60 FPS 候选中位≥57、P95≤25ms。加载/进入后台窗口单列，不删掉来粉饰战斗指标。20 次循环无持续线性增长和闪退；未达标标记不支持该档，不自动放宽阈值。
**注意**：统计帧间隔包含刷新/呈现节奏，不等于单独 GPU 帧时；温控可能随系统、壳与环境变化，30 分钟是首轮测试而非全部场景保证。
**Kimi 本步任务**：提供原始长测记录和瓶颈定位；没有三台设备只能写缺失项，不能宣告关卡 C 通过。

### 第 12 步：明确中继地址与安全连接（10～18 小时）

**前置**：至少一台通过关卡 C，或已明确仅在候选设备验证。**允许范围**：平台网络配置、Transport 地址选择、必要服务端配置与调试日志；不自动部署。

**如何做**：
1. 改 relayURL 选择顺序：受控开发覆盖（仅 debug）→ 原生 Android 使用明确配置的生产 WSS → 普通网页保留原有 LAN/生产选择。release 原生壳缺生产地址时明确禁用联机并提示配置错误，禁止退回 ws://localhost:8787。
2. 首轮可显式使用现有 PROD_RELAY 作连通性候选，但它是上游服务，不能据此承诺可用性、配额或部署权限。正式版使用用户控制的 HTTPS/WSS 域名与 Worker 配置，记录实际地址并验证证书。
3. 在 debug APK 观察握手真实 Origin，和服务端 ORIGIN_OK 比较。当前代码已允许 localhost/私网源，不能不看请求就扩大到 `*`；白名单不提供身份认证，也不是防作弊方案。
4. release 只走 WSS；不使用全局 cleartext 或 mixed-content always allow 修复联机。调试私网 ws 仅限 debug manifest/安全配置，并有对应 HTTPS/WSS 或调试源设计，发布前产物检查不得保留例外。[Android 网络安全配置](https://developer.android.com/privacy-and-security/security-config)
5. 手机的 localhost 指手机自身；连电脑本地中继要用明确的电脑 LAN IP、相同 Wi-Fi、0.0.0.0 监听和必要防火墙规则。若 APK 页面是 HTTPS，仍检查 WebView mixed-content 限制，不能只改 IP。
6. 先两台手机，再手机+桌面，最后 4/8 人目标房间；验证建房、加入、开赛、移动、墨水、技能、结算，不只访问 /health。
7. 协议、Origin、证书、DNS、无网与房间满/比赛中等错误分别显示稳定错误码。日志保存主机 ID 与本地角色归属，不存姓名、房间码等不必要个人信息。

**验收**：断开电脑服务后生产构建仍可连已配置中继；release 没有 localhost:8787、明文例外和调试覆盖入口；手机与桌面实战同步。
**注意**：Network 插件只能说明接口连通状态，不证明 WSS 服务可达；浏览器 WebSocket Origin 限制也不等同 fetch CORS。[Network 插件](https://capacitorjs.com/docs/apis/network)
**Kimi 本步任务**：消除原生 localhost 误判并验证端点；需要正式域名/账号时列阻塞，保留离线版可运行。

### 第 13 步：弱网、切网和断线 UX（8～16 小时）

**前置**：12 正常联机。**允许范围**：Transport、Session、平台网络监听、网络状态 UI；首版不自动加身份恢复协议。

**如何做**：
1. 状态区分 connecting/online/suspect/disconnected/rejoining-lobby；底层 socket OPEN 不等于在线，心跳逾期需明确状态。连续约 6 秒无有效响应进入 suspect，本地禁止提交新操作，并按前后台策略处理；与服务端 20 秒静默清理分工，不假装立刻恢复主机。
2. 单一连接负责人：每次建立连接递增 generation，所有 timeout、旧 socket 回调及重试必须检查同一代；页面恢复、networkStatusChange 和 onclose 不能各建一个 socket。
3. 首版掉线后结束本地旧对局并清理，再提示返回大厅重新加入；大厅重连用指数退避 1/2/4/8 秒、最多 5 次、带少量抖动，前台才重试，用户取消立即停止。
4. 房间仍在比赛时服务器当前拒绝加入，保留“比赛进行中/等待下一局”提示。重建 WebSocket 得到新 memberId 不等于恢复旧玩家；重连原身份必须另设计 token、席位宽限、状态全量恢复、去重与超时，单独估时。
5. 若发生发送积压，监测 bufferedAmount，初始软阈值 64KiB、硬阈值 256KiB，仅作观测起点。状态快照在送入 socket 前按类型合并为最新；伤害、投掷、死亡等可靠事件不得随意丢。硬阈值持续 3 秒触发受控断线，不无限缓存；先统计正常高峰再定最终阈值。
6. 现有 netlag/netjitter/netspike 只模拟接收入站延迟及保序卡顿，不是 TCP 丢包。另用可控路由器/网络代理测试带宽限制、真实断链与系统切网，记录如何施加条件。
7. 每种场景至少 10 次：Wi-Fi→蜂窝、蜂窝→Wi-Fi、飞行模式 5/15/30 秒、断网后恢复、锁屏 30 秒/2 分钟、快速前后台；观察旧回调不会回填新会话。

**验收**：UI 不永久停“连接中”；最多一条有效连接/一组心跳；断线不继续计本地已失效的成绩；达到重试次数后有可执行出口；不能因 new socket 就把旧比赛显示在线。
**注意**：不添加保持 CPU 唤醒或后台服务去保证整局不掉线，首版以恢复边界明确为准。
**Kimi 本步任务**：实现可解释失败和大厅重连，不扩成无缝续局；为每种切网留证据。

### 第 14 步：房主迁移与一致性（8～14 小时）

**前置**：13 完成。**允许范围**：既有服务端选主、NetMatch onLeave/_adopt、Boss 接管与必要测试。

**如何做**：
1. 保留中继“最早存活成员”选主，客户端只接受服务端 host 通知；不同时用本地超时和服务端选举各自宣布主机。
2. 四端房间依次测试房主主动退出、杀进程（socket 关闭）、冻结/断网（半开）、房主锁屏。后两类按静默阈值及 SWEEP 等待，不能要求和主动退出一样快。
3. 暂定目标：健康网络主动退出后 3 秒内收到新主机并继续；冻结/断网后在 20 秒静默+最多一次 4 秒 sweep+额外 6 秒网络/调度预算内恢复，即约 30 秒测试预算。该值是当前实现导出的验收候选，不是系统级硬保证；超时失败要诊断，不能隐瞒。
4. 检查新主机 follow=false、角色 owner 更新、Bot 接管/人类专用图移除、插值缓冲清理和 Boss adopt/handoff；不把所有原玩家位置瞬移到出生点。
5. 比较剩余时间、区域归属、Boss 血量、死亡/复活、装置存活、已触发伤害与最终结果。一次事件只能产生一次效果；全房同一时刻仅一个计时/结算权威。
6. 旧主机回到前台时必须接受已失去身份并回大厅，不与新主机争权。新旧消息按 sender/epoch 或已有归属规则过滤；若增加 authority epoch，应定义协议兼容并覆盖所有权威事件，不只给快照打标。
7. 当前迁移若不能完整恢复某些装置/墨水状态，应记录具体丢失字段并加同步恢复；不得凭角色还能走就宣布迁移正确。

**验收**：每模式 10 次迁移无双房主、重复大招、计时倒退和二次结算；1 位幸存者也能明确继续或退出；无人存活时退出房间，不永远等待。
**注意**：共享 WebSocket/TCP 有队头阻塞，换成 WSS 不会消除弱网抖动；中继也不是完整权威战斗服务器。
**Kimi 本步任务**：沿现有接管接口补测试与修复；不另建不兼容选主方案。

## 6. 三项重点的独立检查表

### 6.1 触屏手感：优先级最高的交互问题

| 项目 | 操作/实现细节 | 失败判定 |
|---|---|---|
| 指针归属 | 按下绑定 role，滑出区域仍归原角色，结束/cancel 释放 | 右指过按钮抢走视角、左指拖出后一直走 |
| 单位 | 拖动用 CSS px×rad/px，不乘 dt/DPR；摇杆用 rad/s×dt | 换屏幕 DPR 或 30/60 FPS 后转速翻倍 |
| 开火+瞄准 | 开火指针与视角指针可并存，开火按钮可留在右侧视角区上层 | 第三指按开火让右指失效 |
| 蓄力/投掷 | held 与 released 均进入统一快照，取消有显式路径 | 松副武器即主武器开火、摇罐等级丢失 |
| 失焦 | 清所有指针、按住、增量及蓄力，恢复先确认 | 回前台自动扔雷、持续射击 |
| 死亡/地图 | 玩家不可动但地图允许预选，坐标含翻转/安全区 | 点队友选到敌方、关地图误射 |
| 参数调优 | 一轮只改一类变量，同任务重复三次并保留意见 | 只在 PC 拖动鼠标说手机手感通过 |
| 无障碍/疲劳 | 左手模式、按钮大小/位置可调，连续持机 10 分钟 | 手指遮视野、频繁跨屏、按钮够不到 |

默认先用手动开火，不把自动开火和陀螺仪混进基础验收；需要时在基础达标后另开功能任务。

### 6.2 持续性能：看最慢设备的热机窗口

内存测算只作排查起点：单张 4096×4096 RGBA8 纹理约 64 MiB，2048×2048 约 16 MiB，不含 mipmap、双缓冲、深度、浏览器内部副本；RGBA16F 还会更大。应统计同时存活目标，而不是只看一个 paintAtlas 数值。降低屏幕 DPR 不一定降低墨图集内存。

必须单列 CPU Bot/物理/墨网格开销和 GPU 阴影/后处理/透明粒子开销。rAF 帧间隔慢不能直接判成 WebView 太差。首版优化顺序为：正确移动低档 → 分辨率 → 阴影/后处理 → 纯视觉粒子与装饰 → 明确定位后的 CPU 热点。减少模拟精度、改变碰撞体和比赛规则需要另评估网络一致性，不能作为手机专属随意修改。

除 30 分钟战斗外，至少做 20 次地图循环和 10 次前后台循环。上下文恢复要验证墨迹、资源、控制器与会话的完整状态；只收到 webglcontextrestored 事件不能勾选恢复成功。

### 6.3 手机联机：分清五种不同问题

1. **连不上**：地址、TLS、Origin、协议号、权限、DNS；先读错误再改服务配置。
2. **连着但不动**：半开 socket、后台冻结、心跳计时和快照年龄；用有效 pong/状态消息判断健康。
3. **抖动/瞬移**：插值缓冲、外推上限、恢复后旧快照堆积；展示状态年龄与纠偏统计。
4. **掉线重入**：当前没有承诺原身份续局；首版提供明确退局/回大厅。续局需要服务端协议和凭证，不只是 reconnect()。
5. **房主丢失**：服务端成员清扫与选主、客户端归属接管和完整状态恢复；覆盖 Turf、Zones、Boss，而不只普通角色运动。

弱网预设（额外网络条件，不把所有数值误称最终 RTT）：

| 档位 | 条件 | 目标 |
|---|---|---|
| N0 | 稳定同 Wi-Fi，先记录实际 RTT | 基线同步、开赛/结算一致 |
| N1 | 现有 netlag=60、netjitter=30、netspike=0.01 | 测试保序延迟；不出现无限纠偏/重复效果 |
| N2 | 真实网络工具施加约 1Mbps 下行/256Kbps 上行并记录延迟 | 无无限发送积压，必要时受控退出 |
| N3 | 完全断网 5/15/30 秒再恢复 | 状态机可解释，不把旧包注入新局 |
| N4 | 房主断开/冻结，Wi-Fi 与蜂窝切换 | 按迁移预算恢复或明确失败，无双权威 |

工具若不能精确施加丢包，不填写“已测试 5% 丢包”；TCP 重传/队头阻塞与应用入站延迟是两种条件。
