# v24：仅手机Boss高频短音缓存

## 问题与证据

2026-10-26，当前HONOR ALP-AN00 / Adreno730。v23音效名称调查一分钟，2倍/SMAA/8人，正常输入游玩；有方法探针，不是正式成绩。平均28.435FPS、p95约50.1ms、p99约66.6ms、100ms以上4帧；USB文件INKWAVE-logs-20261026-102414-752463-e410c561.json已核对，游戏关闭。

| 音效 | 调用/实际播放 | 创建节点总数 | JS累计耗时 |
| --- | --- | --- | --- |
| roller_flick（滚筒挥击） | 233/214 | 7490 | 401.2ms |
| splat_small（墨滴落地） | 912/357 | 4975 | 310.6ms |
| shoot_shooter（普通射击） | 296/296 | 5920 | 301.0ms |

三种合计约1.013秒JS调用耗时，还会生成大量原生音频节点。此前CPU分组轮暂停单发音效新建后模拟耗时下降；这些不是严格因果帧率对照，因此本批必须重新构建和正式实测。

## 修改边界

- 只在手机Boss准备队列中，为上述三种无状态短音各烘焙4种随机变体。原配方离线合成，和真实AudioContext相同采样率；逐种准备、可取消、单变体2秒超时。失败回原配方，不让音效缓存阻断开局。
- 缓存限8MiB，每个样本最长1秒；浏览器48kHz实测12个样本共1428984字节，约1.36MiB。重复开Boss复用，不在战斗内补烘焙。
- 战斗中命中缓存用单个BufferSource，保留原音量、HRTF位置、距离低通、共享混响、同名间隔、并发上限、偷音淡出及结束释放。空间射击从约20个节点降到5个。
- PC和普通对局走原程序化建图；连击状态音hit_marker、循环、其他音效不缓存。未知调用参数或最终音高不在0.65～1.5时原配方回退。
- 听感取舍：由无限随机合成变为4个样本轮换，仍叠加原随机音高；样本整体变调会同时改变包络时长，而原配方部分包络与音高独立。图像、分辨率、SMAA、人数、伤害和模拟规则不改。尚未做人耳听感验收。

## 基础验证与复现

先启动本地工作区HTTP服务8490，再运行：

```powershell
node tools/check-js.mjs
node tools/check-mobile-boss-preparation.mjs
node tools/check-boss-audio-cache.mjs
```

缓存专项使用Windows Edge真实OfflineAudioContext：三种样本与相同种子原配方逐点最大差约5.96e-8；变体不同且PCM有限、非静音；重复缓存、取消、异常回退、内存上限、非Boss路径隔离、空间/混响链、参数回退、自然结束释放通过。结果在本地releases/investigation/boss-audio-cache-browser.json，不随Git同步。这些验证不证明真机FPS。
