# test8：同一Wi-Fi上传诊断日志

更新日期：2026-10-23（北京时间）。本批只增加诊断上传，不修改渲染质量、帧率目标或游戏模拟。

## 使用

1. 电脑仓库根目录运行 `py -3 tools/log_receiver.py`，保持窗口/进程运行；接收器监听8765端口。
2. 只为同一子网放行电脑防火墙TCP8765；手机与电脑在同一Wi-Fi，访客隔离/VPN可能阻断连接。
3. 安装已配置这台电脑局域网地址的test8 APK，在实际对局内点顶部“上传日志”。显示“上传成功”及文件名才表示电脑已确认保存。
4. 日志写入仓库的 `releases/logs/`（本机仓库为 `D:\DemoInk`）。目录由接收器创建，不随Git上传。下载服务仅公开 `releases/mobile-install/`，不公开日志目录。
5. 电脑无法连接或保存失败时会显示错误，按钮恢复可重试；原“导出日志”仍可使用。没有自动上传或后台重试。

新电脑/电脑IP改变时，在当前终端设置实际地址，然后按构建指南重新构建：

```powershell
$env:INKWAVE_LOG_UPLOAD_URL='http://电脑局域网IPv4:8765/api/logs'
./tools/build-android.ps1 -JdkPath '本机JDK21路径' -SdkPath '本机SDK路径'
```

环境变量同时供网页构建和Gradle使用；未配置的APK会明确提示无法上传，原导出功能仍可用。APK使用原生HTTP上传，避免WebView混合内容/CORS限制；Gradle只接受RFC1918局域网IPv4、8765端口和 `/api/logs` 路径，生成的网络策略只为该地址允许HTTP，其余地址继续禁止明文。地址不硬编码进源码。

## 数据和失败边界

- 上传现有JSON报告（当前/上一运行、GPU/着色器信息、性能样本），只在用户点击时采集和发送。上限4MiB，与原生本地导出一致。
- 服务端校验JSON和诊断格式，服务端生成唯一文件名，客户端不能指定文件路径；完整写入后原子改名，成功才返回201和文件名。
- 明文局域网诊断接口没有用户账户认证，只应在可信Wi-Fi临时运行；不开放公网端口。诊断文件可能包含设备及游戏运行信息。
- APK下载与接收器共用8765端口，启动接收器前须停止原 `python -m http.server 8765`，不能同时占用同一端口。
- 本机新debug签名与原电脑不同。可覆盖本机test7签名的安装；若手机仍是原电脑签名，不得直接卸载丢进度，应迁移原签名重建。
