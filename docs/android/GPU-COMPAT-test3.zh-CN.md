# 测试版3：手机GPU兼容与PC效果隔离

## 根因与处理范围

用户日志 INKWAVE-logs-20261021-102317-430 显示：华为 PLA-AL10、Maleoon 920、华为WebView 114，片元 uniform 上限256组。原地面着色器仅材质表、尾迹、涟漪与壁画数组就占282组，编译报 `too many uniforms`，地面与格栅链接失败。墨迹图集仍有写入，因此表现为计分继续但场景与墨迹不可见。

本版针对这个已确认的原因修复；不能承诺所有GPU驱动永不出错。策略是降低手机资源依赖，失败时自动降级，最低档失败时明确暂停并保留日志出口，避免继续在缺失地面的场景中游玩。

## 手机独立路径

1. 只有移动入口存在 `inkwaveMobile` 时才启用专用材质与GPU保护。网页PC仍调用原 `createLevelMaterial`，不安装手机降级逻辑。
2. 将材质/壁画参数表从大量uniform数组移到小型浮点数据纹理；只采样原有颜色纹理，移除手机地面法线/ORM、复杂尾迹与涟漪数组。
3. 默认使用简化标准材质，保留场景颜色纹理、壁画、格栅孔洞、墨迹覆盖和队伍色。减少复杂高光、水墨动态波纹及遮挡消隐，手机视觉不保证与PC一致。
4. uniform或纹理资源不足时直接选基础材质；复杂手机材质编译失败时，在当前渲染后重建基础材质并立即重画。基础材质保留场景顶点颜色、格栅孔洞及墨迹，不保留原场景贴图与光照质感。
5. 基础材质或墨迹核心程序也编译失败时安全暂停、清空触屏操作、显示提示，仍可“导出日志”。不会无限重试或静默丢失地面。
6. 手机墨图集最大2048并受设备纹理尺寸限制；多重采样不超过设备上限；没有浮点颜色附件扩展时后处理目标改用8位。PC继续使用原参数。

主要文件：`src/platform/mobileGpu.js`、`src/world/mobileLevelMaterial.js`；接入点为 `src/core/renderer.js` 与 `src/main.js`。原PC地面/水墨着色器文件未修改。新增逻辑含中文注释。

## 已执行的本地验证

- 实际链接后的手机地面/格栅程序，保守合计顶点与片元active uniform，约48～49组，最大数组长度1；基础档约20组。
- 模拟报告256组与224组限制，两档均成功启动、显示场景与写入墨图集；独立像素读回验证主档和基础档真正画出红队墨迹。
- 向测试材质实例注入真实非法GLSL，确认自动降级；再次破坏基础档，确认安全暂停且日志按钮存在。故障注入仅在测试工具，不打入APK。
- 同一台电脑、浏览器、地图和画质下，PC三组原有顶点/片元程序逐字节哈希一致；高画质默认、物理材质及手机策略未启用的断言通过。
- 移动离线启动、四指输入、后台恢复、左手布局、区域罚分结算、完整短局，以及诊断导出/原始编译错误/跨重启留存回归通过。

限制：上述资源上限为桌面浏览器模拟报告值，实际编译仍使用桌面GPU，不等于Maleoon真机验收；触屏手感、30分钟热机与多人切网验收仍需手机实测。

## 重复验证方法

1. 在项目根目录执行 `npm run build:mobile`，然后另开终端运行 `python -m http.server 8490`。测试期间不要重建网页资产。
2. 执行 `node tools/check-mobile-gpu.mjs`。需要本机Edge；其他安装路径通过 `EDGE_PATH` 指定。
3. 报告写入 `releases/investigation/mobile-gpu-check.json`，截图在同目录。工具断言资源预算、可见墨迹、降级、安全暂停及PC入口。
4. PC逐字节比较需要改动前在同一环境采集的JSON基线（结构：`levelShader: [{hash: [顶点SHA256, 片元SHA256]}]`），可通过 `PC_SHADER_BASELINE` 指定；默认读取本次本地调查基线。没有基线会明确跳过GLSL比较，不能记为通过。
5. 运行 `npm run check`、`npm run check:mobile`、`node tools/check-diagnostics.mjs` 和 `node tools/check-mobile-network.mjs`；Android构建使用既有 `tools/build-android.ps1`。

## 手机验收顺序

1. 覆盖安装版本 `1.1.0-android-test.3-compat`（versionCode 3），不要先卸载，避免清除旧设置与日志。
2. 冷启动进入练习：确认地面、墙面、格栅存在；向地面和墙面射击，确认墨迹和计分变化一致。
3. 连续移动/瞄准/射击/潜墨，检查各地图与武器；切后台再恢复。若画面质感更简单，查看日志是否发生正常基础档降级。
4. 运行30分钟，记录前5分钟与最后5分钟帧耗、温度体感、卡顿及场景是否异常。较低帧率不等于编译失败，需分别记录。
5. 无论正常或异常，都导出一次新日志。核对 `current` 中构建版本为test.3；`previous` 可能仍保留test.2历史错误，不要误判为本版新错误。
6. 回传日志及异常地图/武器/操作；如出现安全暂停先导出，再重启。不要将暂停绕过后当作正常兼容。
