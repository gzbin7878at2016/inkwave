# Android 测试版：构建与手机验收

本轮交付是可侧载的签名 **debug 测试包**，不是商店正式版。单机玩法使用 APK 内置网页、Three.js、字体和素材，不依赖电脑或外部 CDN。多人模式使用公网中继，需要网络；当前没有承诺原局自动重连。

## 1. 手机安装与第一次测试

1. 在 `J:\DemoInk\releases` 找到 `INKWAVE-android-test1-<源码提交号>.apk`，复制到手机。使用 Android 10 或以上，先更新 Android System WebView/Chrome。需要设备支持 WebGL 2 / OpenGL ES 3；系统版本满足不等于 GPU 一定支持。
2. 用手机文件管理器打开 APK，按系统提示允许该文件管理器安装应用，再安装。应用包名是 `com.demoink.inkwave`，显示名 INKWAVE。
3. 横屏启动，等待加载。首次使用低画质、关闭阴影/泛光、30 FPS。右上角“触屏练习”可直接进入无计时单人练习；原游戏菜单还提供离线机器人对局。
4. 左侧摇杆移动；右侧空白处滑动转视。按住“开火”也可拖动瞄准，便于两拇指游玩；另一个手指仍可独立转视。按住副武器瞄准，松开投掷；取消触摸/切后台会放弃蓄力。跳跃、潜墨、大招、欢呼各有按钮。
5. 点击“地图”保持打开，点击“队友1～3/基地/信标1～6”复用原有跳跃目标校验与阵亡预选逻辑，再点“地图”关闭。不可用目标不会执行跳跃；地图仍保留部分桌面提示文案，后续需要根据手机体验优化。
6. “触控设置”可调灵敏度、按钮大小、左手瞄准布局、30/60 FPS。保存后恢复游戏。优先在 30 FPS 完成测试，再试 60 FPS，不能因为可选 60 就认为所有手机能持续达到 60。
7. 切后台会暂停单机并释放所有输入；回来点击继续。多人房间在后台/断网时主动退出，回来重新加入。Android 返回键在对局里切换暂停，在主菜单询问退出。
8. 开飞行模式后完全结束进程并重新启动，进入练习和离线机器人对局，验证手机真实冷启动离线能力。浏览器禁止外站请求的回归只能证明资源自包含，不能替代这一步。

覆盖安装要使用同一签名。换电脑重建时默认 debug 证书可能不同；遇到签名冲突先记录错误，不要直接卸载掩盖数据保留问题。卸载会删除应用内设置/进度。当前没有生成或托管正式 keystore。

## 2. 可复现构建

先在仓库根目录运行 `npm ci`，确认 Node 22+；本次使用 Node 24.14.0 / npm 11.12.1。依赖锁定在 package-lock.json。Capacitor core/android/cli 8.5.3、App 8.1.2、Network 8.0.1、esbuild 0.28.2。

准备 JDK 21、SDK platform-tools、API 36、Build Tools 35.0.0（AGP 默认构建版本）及 36.0.0（签名验证也可使用），接受 SDK 许可证。工程为 AGP 8.13.0 / Gradle 8.14.3，最低 API 29，目标 API 36。

本机隔离位置：

```powershell
# 不修改系统 JAVA_HOME，也不修改 UE4 SDK。此命令在仓库根目录执行。
./tools/build-android.ps1

# 其他电脑明确指定 JDK 和 SDK 目录；路径不要求与本机相同。
./tools/build-android.ps1 -JdkPath 'C:/tools/jdk-21' -SdkPath 'C:/tools/android-sdk'
```

脚本依次做语法检查、移动传输回归、网页构建、Capacitor 同步、assembleDebug、签名验证，成功才复制到 `releases` 并生成 SHA-256 和 `android-build-info.json`。脚本会记录源码提交及是否有已跟踪未提交变更；交付时应为干净源码。`android/local.properties` 不进 Git。

网络受限时，先确保本机代理可用。仅在当前 PowerShell 进程里设置 Java 下载代理，例如本机 Clash HTTP/混合端口为 7890：

```powershell
$env:JAVA_TOOL_OPTIONS='-Dhttps.proxyHost=127.0.0.1 -Dhttps.proxyPort=7890 -Dhttp.proxyHost=127.0.0.1 -Dhttp.proxyPort=7890'
./tools/build-android.ps1
```

端口按实际配置替换。代理不写入仓库，也不会被 APK 使用。生产中继目前沿用 `wss://inkwave-net.inkwave.workers.dev`，其可达性和运营不由此仓库构建保证；禁止明文 HTTP/WS，不能直接用 `ws://局域网IP` 在该包里联机。

### 浏览器集成检查

开两个终端，根目录执行：

```powershell
# 终端一：静态服务
python tools/serve.py 8490

# 终端二：先构建，整个测试运行期间不要再次构建/删除 dist-mobile
npm run build:mobile
npm run check:mobile
node tools/check-mobile-network.mjs
```

默认使用本机 Edge，可用 EDGE_PATH 指向其他安装位置。自动检查覆盖禁止外站访问的移动启动、合成四指输入进入真实控制器、原生浏览器触屏捕获/抬手、取消蓄力、后台恢复、左手布局、罚分区域结算、短局完整结算及桌面入口。截图/JSON/日志放在 releases，不进入 Git。Edge 软件渲染的 FPS **不能当手机性能结论**。

## 4. 三项重点的真机执行表

### 触屏手感

同一关卡/同一灵敏度连续做三轮，每轮记录按钮大小、左右布局、帧率、DPR/WebView。先用两拇指移动+开火拖瞄，再增加第三指跳跃；再用四指移动+独立转视+开火+跳跃。每项持续30秒，滑出区域后抬手、系统打断触摸都不得卡走/卡火。

依次测试射击枪、蓄力枪/转轮类、滚刷类和每种副武器：按住蓄力→正常抬手应按规则释放；按住→切后台/取消应放弃攻击。死亡时打开地图预选、重生执行，基地/队友/信标失效时不能跳到错误目标。开地图不能走火。大招瞄准使用右侧拖动、开火确认，单独记录失败武器。

每轮只改一个参数；记录误触次数、是否够得着、10分钟持机疲劳。当前只支持预设左右布局和整体按钮大小，任意位置编辑是明确剩余项。手机系统抢占三指手势时，先确认两拇指方案仍可用，不把系统事件缺失误判为游戏已收到输入。

### 持续性能与内存

1. 充电关闭、后台应用固定、亮度固定，先冷机跑5分钟，记录机型/芯片/室温/系统/WebView/目标FPS。不要使用软件渲染自动化数据设预算。
2. 同地图同模式连续30分钟，在第1/5/10/20/30分钟点“诊断”截图并“复制报告”保存JSON。报告含实际帧间隔P50/P95、FPS、动态比例、draw calls、三角形、纹理/几何数量、可用时JS堆、RTT。
3. 记录表面温感/系统温度工具数据、电量变化；当前没有原生温度采集，报告里没有温度时不能写“无降频”。P95来自最近240帧滚动窗口；样本每约一游戏秒记录，最多1800条。
4. 先以30FPS目标测试，P95预算可先定≤40ms；60FPS探索档先定≤22ms，按设备实测校准。记录持续超预算时的地图、Boss/特效数量、分辨率比例；CPU/GPU分别用Android Studio Perfetto/Profiler定位，不能盲目只降低分辨率。
5. 完成5次“进对局→菜单→换图→再进”，取每次稳定后纹理/几何/堆指标。持续单调上涨且不能回落要查 dispose、事件监听、音频/材质池；峰值上涨后平台稳定不能直接判泄漏。
6. 通过前仅默认低档30；若60热机失败保留30，不用“首分钟达到60”替代持续性能。

### 手机联机稳定性

1. 先手机+桌面两端，再双手机，确认版本/协议一致、WSS可达；记录房主、加入时间、开局/结算、RTT及掉线提示。不要为了测试部署/覆盖公共中继。
2. 手机客户端切Wi-Fi→蜂窝→Wi-Fi，各3轮；关网络10/30秒各3轮。当前允许结果是明确离房并可重新加入，禁止卡在伪连接、无限积压、无提示继续旧局。
3. 对局按住副武器切后台5秒、30秒、锁屏1分钟；返回后不应自动投掷/射击。测试版会主动离房，应由其他在线成员现有迁移逻辑接管，而不是期待原手机自动恢复房主。
4. 2/4/8人分别让房主正常离房、杀进程、断网；记录唯一新房主、比分/墨迹/角色/投射物和Boss状态是否连续，结算是否一致。连续迁移至少3次；此项未实测前不能承诺稳定多人可玩。
5. 浏览器调试可使用原有 netlag/netjitter/netspike 参数做延迟与抖动；它不能完整模拟真实丢包/蜂窝切换，须结合设备网络限速和真实切网。当前交付包没有专门的 relay/弱网设置界面。
6. 失败记录格式：构建文件名/提交号、机型、WebView、网络、房主身份、复现步骤、发生秒数、录屏/截图、复制的诊断JSON。优先修卡火/黑屏/双房主/结算错，再优化重入步骤。

## 5. 后续时间估算

剩余主要由设备矩阵和实测反馈决定。拿到三档手机后，触屏/武器真机回归与调参约12～24小时，热机/内存与热点优化约12～28小时，弱网/切网/迁移验证及已复现缺陷约16～36小时，安装升级/全量地图模式回归约8～20小时。合计约48～108个有效工时（6～14个8小时工作日）；若出现驱动兼容/Boss迁移深层问题另计。不能把本轮首个测试APK的构建时间当作原计划129～227小时全部完成。
