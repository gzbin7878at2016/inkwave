# v49：清理手机Boss失效的就绪反馈

## 问题与范围

真实HUD和正式CSS复现：8个槽先specialReady=true，再false，is-ready虽已移除，is-readyflash仍存在；后者的CSS包含iw-sq-glow无限循环。因此大招消耗后仍有就绪光晕，死亡或空槽也可能继续计算已经失效的反馈。这与v46纯装饰静态化不同，本次**保留真正就绪时的原闪光、旋转和循环光晕**。

仅Android正式Boss的HUD._updSquads在状态键改变时，消耗大招/死亡后移除is-readyflash；空槽移除is-ready及is-readyflash。已有脏键缓存保持，同状态不重复写DOM，无新增计时器、逐帧动画枚举或样式读取。PC、普通模式、演示与菜单沿用原状态路径，玩法/音效/人数/物理AI子步/2倍SMAA保持。

v48涂地重播候选已在eb356f0撤回；v49恢复原8份关键帧/7组反馈，不将该候选继续叠加。v47同热对照18.46346FPS、v48复测17.98329FPS且Worker超时，均未稳定30；详情见test48，不把约0.48FPS差归为严格版本因果。
