# 固定2倍高清性能优化：第一批（测试版7）

本批建立可验证的性能基线，不宣称已经提高帧率。固定2倍高清、60帧目标、关闭自动降分辨率及现有模拟保持不变；PC不安装手机统计器。

## 统计内容

- 每4个游戏帧取样CPU时间，分为input、simulation、effects、environment、camera、paint、prepare、draw、ui。prepare含声音/参数更新；draw含场景和后处理命令提交，尚未逐Pass分解。total包含HUD和菜单，修正原日志漏掉帧尾界面时间的问题。
- 保留最近120个CPU样本，各阶段输出P50/P95。各阶段P95不能相加作为total的P95；数值不是GPU完成时间，也不含浏览器合成。
- 每120帧从Three.js真实renderBufferDirect前后计数差值记录绘制；实例数量按渲染器实际统计。同名合并，最多200组，输出三角形前20和绘制次数前10。未命名对象用几何/材质ID区分，ID只在当前运行有意义。
- 模式/地图/对局阶段变化时清空CPU窗口与排行榜，防止混用大厅和实战数据。drawAt标记最近抽样时间，不能把旧排行当作实时平均。
- 每秒报告带mode、matchState、pixelRatio及profile，保留最近300条（约5分钟）；CPU缓冲和排行榜均有界，不逐帧写文件。导出仍由用户点击触发。
- 本批不提供“隐藏某类对象”的运行开关，也不直接减少三角形；先用排行选择下一批对象，再做逐项真机对照。

## 验证方法

1. `node tools/check-mobile-profiler.mjs` 检查分段计时求和、真实绘制计数、返回值、未命名对象区分、缓冲上限和上下文隔离。
2. `npm run build:mobile`，本地8490服务启动后执行 `npm run check:mobile`，检查真实地面绘制被统计，同时验证固定高清、触屏、后台、完整短局和PC入口。
3. `node tools/check-diagnostics.mjs` 检查code7、导出、错误捕获和重启留存；另执行语法及网络回归。

## 手机逐步验收

1. 覆盖安装测试版7，无需卸载；进入触控设置确认60帧、2倍高清、自动降低清晰度关闭。
2. 进入实际对局，等待开场结束；正常移动、转向、射击和使用大招，至少运行2分钟。不要只停在大厅或练习。
3. 在仍处于playing状态时点击导出日志并回传。profile.samples应大于0；topDraws/topCalls应有数据；该手机pixelRatio应为2、canvas应约1540×752。
4. 同地图再进行10分钟/30分钟热机，结束前再导出，观察最后5分钟的帧耗和对象排行。切回菜单后会重置统计上下文，因此应在退出对局前导出。
5. 本批通过的标准是日志可用、2倍未变、玩法无回归；下一批才依据真机数据减少最贵的对象/更新。不能凭桌面浏览器FPS宣布手机60帧达成。

下一批选择原则：CPU total接近或超过16.7ms时先定位simulation/ui等高耗时阶段；CPU较低但帧间隔仍大时再对照几何、后处理和浏览器合成，不能直接认定GPU瓶颈。绘制排行只决定优先调查对象，不代表三角形最多的对象一定最耗时。每次只优化一类对象/更新，并用相同地图、路线、武器和热机时长对照。
