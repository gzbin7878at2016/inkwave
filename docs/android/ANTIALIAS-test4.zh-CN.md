# 测试版4：手机清晰度与抗锯齿

## 本次依据

测试版3真机日志 `INKWAVE-logs-20261021-105141-355` 中着色器失败为0、地面与格栅链接成功、手机材质为textured且未降级。89个性能样本FPS中位数29，但有9个低于25；不足以承诺提高画质后仍稳定30帧。

视频栏杆、角色与建筑轮廓有明显阶梯。日志窗口770×376、DPR3.5，但低档渲染密度只有0.75，实际约577×282，动态scale0.875后约505×246；低档又关闭MSAA且未补后处理抗锯齿，是本次优先修复点。

## 修改内容与边界

1. 只有手机低画质使用单独的密度1.0参数，其他低档粒子/阴影等预算保持原值；共享QUALITY对象和PC参数不改。770×376窗口的基础目标约770×376，相比0.75密度像素量增加约78%，需真机确认功耗与帧率。
2. 手机没有MSAA时，在OutputPass后加单遍FXAA，处理3D画面，HTML界面不受该滤镜影响；有MSAA时不叠FXAA。PC继续原MSAA/SMAA逻辑。
3. 窗口、画质、DPR或动态缩放改变后，根据真实目标尺寸更新FXAA采样步长；重建时释放旧FXAA资源。
4. 日志 `current.scene.render` 新增pixelRatio、canvas与target的实际像素尺寸、antialias和fxaaTexel，方便区分低分辨率与编译错误。
5. 动态分辨率自保、手机GPU降级和墨图集2048上限继续保留。本版未实现SMAA对比设置、墨迹专用边界改进或新特效预热，不将这些后续工作算作已完成。

版本：`1.1.0-android-test.4-aa`，versionCode4。

## 验证与手机对比

自动检查使用 `node tools/check-mobile-gpu.mjs`：除原资源预算/降级/可见墨迹外，在实际后处理链读取黑白斜边像素，对比FXAA开关；检查非整数动态缩放、窗口变化、中低档切换后的真实尺寸与采样步长，并对比PC着色器基线。完整移动与诊断回归命令沿用测试版3说明。

安装后按同地图、同武器、同路线测试：先观察栏杆斜边、角色轮廓与远景，随后移动转向和射击，记录画面改善及卡顿；持续运行至少10分钟再导出日志，有条件执行30分钟热机。重点看是否仍接近30帧、是否频繁降低scale、手机是否明显变热。FXAA会略软化边缘，不能弥补所有低分辨率细节。

本地已通过：FXAA斜边开关对比中4620个像素发生变化，1705个原黑色边缘像素形成过渡；非整数缩放、窗口变化及画质切换后的采样尺寸一致；256/224资源限制模拟与故障降级通过；移动完整回归无页面/资源错误；PC三组原GLSL逐字节一致。这些数据证明功能接入有效，不是手机主观画质或性能收益量化。

诊断错误捕获、日志下载/JSON解析、跨重启留存回归通过；语法检查182个文件与移动网络确定性回归通过。只依据本地浏览器验证不能证明Maleoon真机效果或功耗通过。
