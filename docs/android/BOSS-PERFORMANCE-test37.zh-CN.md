# Boss第37批：修复SMAA天空色伪边缘

## 为什么从缓冲格式改为先修清屏

检查紧凑格式候选时发现更直接的逻辑问题：本项目renderer清屏色是0x9fd8f0；SMAA边缘shader对无边缘像素discard，不写零。继承的全屏绘制若自动以天空色清屏，边缘纹理未写区域便留下非零红绿值，后续权重计算会把它们当边缘。局部step标志只能为0/1，天空色的小数值不属于合法边缘标志。

真实WebGL已重现：64×36的完全平坦图，2304像素全部出现天空色非二值边缘。黑色清零后2304像素全部无边缘。该问题可能造成额外权重采样和错误混合；需真机验证影响，不能从桌面直接推导FPS。

本批只修手机正式Boss的SMAA清屏，不实施RG8、不改变半浮点边缘/权重/HDR纹理、不改变尺寸、2倍高清、三阶段算法、人数、物理、AI、伤害或音效。PC、普通对局、演示及普通菜单保留原路径。移动端修正后的抗锯齿输出会区别于原错误混合，不应将“与旧错误画面完全一致”作为验收标准；参考是相同算法的正确零边缘输入。

## 如何实现

1. Renderer只在mobileSafety分支同步实际Boss/init预检范围。
2. MobileSMAAPass仅在该范围内，暂时使用黑色alpha0清屏，自动清颜色，避免继承天空色或上一帧标志。
3. 同步执行原三阶段SMAA；已有最后输出融合保留，绘制次数不变。
4. finally恢复调用方的清屏颜色、alpha、autoClear、autoClearColor和Pass.clear；异常同样恢复。使用长期Color对象，战斗帧不新建颜色或状态数组，不新增原生/GL查询。
5. 普通菜单、非Boss、演示、PC和销毁关闭作用范围。加载预检可能仍为menu/init，可使用修复；退出状态由真实Renderer入口验证。
