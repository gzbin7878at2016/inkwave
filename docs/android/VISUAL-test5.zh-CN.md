# 测试版5：手机清晰度与材质层次

## 目标与参考

根据用户提供的本游戏与《蛋仔派对》截图，优先改善软化的轮廓、地面材质层次、墨迹边缘与诊断栏占用。参考图用于判断视觉方向，不是相同场景的可量化基准；本版不替换角色和场景模型，不宣称达到商业原生游戏的整体美术品质。

## 可见变化

| 手机选项 | 基础渲染密度上限 | 默认低几何档的抗锯齿 | 适用情况 |
| --- | --- | --- | --- |
| 省电 | 1.0 | FXAA | 发热或帧率下降时使用 |
| 清晰（升级后默认） | 1.5 | SMAA | 优先清晰度的日常测试 |
| 高清 | 2.0 | SMAA | 接受更大功耗的画质测试 |

选项在“触控设置→画面清晰度”，即时应用并保存。渲染密度仍受设备DPR和动态分辨率影响，不等于固定1080p/原生物理分辨率。清晰档像素量为上一版1.0密度的2.25倍，高清为4倍，不能由桌面验证推断该手机仍能稳定30/60帧。默认帧率继续30，可用既有目标帧率设置选择60。

- 清晰/高清使用现有Three.js的SMAA，遵循本项目库版本要求放在OutputPass之前；省电使用OutputPass之后的FXAA。有MSAA的几何画质档继续使用MSAA，不叠加后处理抗锯齿。
- 动态降档继续运行；清晰/高清尽量不低于1.0个CSS像素的密度。若仍卡顿，用户可切省电获得更大的自保空间。
- 手机地面增加现有ORM纹理读取，区分石材/金属与干湿墨的反光；读取已有lightUv和烘焙遮蔽纹理，补足接触层次。不新增实时AO或高成本实时阴影。
- 墨迹边缘使用屏幕导数适应过渡宽度，并补少量边缘法线变化；不恢复此前导致uniform溢出的尾迹/涟漪数组。
- 缩小顶部诊断按钮字号和高度，保留日志导出入口与主要触控操作。

## 兼容和隔离

只在手机入口启用上述参数与材质。共享QUALITY、PC地面材质、PC原SMAA/MSAA顺序及PC参数保持原有实现。日志增加mobileVisual与SMAA采样步长，沿用实际canvas/target尺寸记录。

主材质新增ORM和烘焙遮蔽采样，最多约9个片元采样器，按10个槽位预留判断能力；不足选择基础材质。SMAA编译失败自动回退FXAA，本次会话不反复尝试；缺少浮点颜色附件扩展也使用FXAA。原有地面编译失败降基础材质、最低档失败安全暂停的出口继续保留。

## 验证方法

1. `npm run build:mobile` 后启动本地8490服务器；测试期间不重建资产。
2. `node tools/check-mobile-gpu.mjs`：实际斜边像素、三档密度、窗口/动态缩放/画质切换、烘焙遮蔽像素、墨迹显示、资源上限及真实编译失败降级；同环境PC着色器基线对比。
3. `npm run check:mobile`：真实设置控件切换三档并验证即时应用/保存，触屏、后台、离线启动、完整短局和PC启动。
4. `node tools/check-diagnostics.mjs`：构建号5、SMAA日志、shader错误捕获、导出及上一运行留存；另运行语法和网络检查。
5. 覆盖安装后，在与旧包相同地图/位置，分别拍省电、清晰、高清三张原始截图；不要只比较经过聊天软件压缩的图片。
6. 清晰档先运行10分钟，观察栏杆、建筑、角色轮廓、地面接缝和墨迹边缘；再进行30分钟热机。记录帧率、scale、实际像素尺寸、手机发热及是否降级。
7. 掉帧时切省电对照；只有高清能接受且帧率稳定时才长期使用高清。导出新日志，核对版本`1.1.0-android-test.5-visual`。

## 已完成的图形检查

- 主材质实际链接预算51～52组uniform（连顶点也合计的保守上界），最大数组长度1，256/224组限制模拟通过。
- SMAA斜边对照读回1290个变化像素、696个黑色边缘过渡像素；实际密度1.5。三档1.0/1.5/2.0切换和动态下限1.0断言通过。
- 同一材质孤立像素测试中，关闭烘焙遮蔽为RGB `[63,88,124]`，启用受控黑色遮蔽图后为 `[22,31,44]`，确认接入生效；不是只添加未使用uniform。
- SMAA真实非法GLSL测试回退FXAA，地面非法GLSL回退保留墨迹的基础档，最低档也失败则安全暂停；均通过。
- PC三组原始GLSL逐字节一致；上述手机参数不进入PC路径。

完整移动回归通过（含真实设置控件三档即时应用/保存），页面异常与资源HTTP错误为0；诊断捕获/导出/留存、182个文件语法与网络确定性回归通过。当前没有连接真机，截图预览不是Maleoon性能验收。
