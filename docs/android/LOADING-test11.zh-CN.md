# v1.0.11：手机开局准备与稳定帧耗

更新日期：2026-10-24（北京时间）。本批代码和浏览器验收已完成；Android产物在干净提交构建后登记。

## 目标与边界

- 按用户最新要求，手机默认目标调整为30FPS，保留30/60FPS选择；固定2倍高清、SMAA和原对局人数不变。旧设置执行本批一次性迁移，PC保持原路径。
- 优先减少开局后突然跌到个位数的长停顿，以及Boss开场和小怪首次出现时的资源准备开销。**这不是已经真机稳定30帧、消除ANR或所有战斗效果均无卡顿的承诺。**
- 允许进入对局前完成必要准备，但必须先显示可操作的进度界面，提供取消和失败出口。进度根据完成的阶段/工作计数推进，不用定时器虚构进度。

## 来自v1.0.10的真机证据

日志：`INKWAVE-logs-20261023-165256-228604-0d19c279.json`，源码`0918cea8e568f7a80b39cd96df317cfb7fbe5966`。

- 启动收尾完整帧41ms，v1.0.9为3598ms；这是两次日志观察，设备状态和场景不保证完全一致。
- Boss对局的`match-setup`为1237ms，随后`match-character-warm-total`为18641ms。已记录的这两段从运行34.719秒至54.598秒，共19.879秒；点击时刻没有完整保留，不能将其写成精确的点击响应时长。
- 上述18641ms是包含异步等待、让帧和8角色/Boss准备的总墙钟时间，不能说成一次连续18.6秒主线程阻塞。运行期最慢浏览器长任务为1630ms，位置接近首角色衣服抖动材质的1649ms预热阶段。
- 8个角色共444步，含404次材质准备；日志只新增15个程序。后续角色大量程序已命中，却仍分别等待约1.3～1.8秒。固定Three.js的`compileAsync()`在没有KHR并行编译扩展时还会逐次等待定时器，因此本批改用明确的程序准备缓存和累计预算让帧。
- 本次报告总长80.298秒、31条性能样本；严格筛选`mode=match && matchState=playing`只有17条，覆盖16.920秒。不可把菜单演示或开场动画计作实战，也不能据此与另一版本直接宣称FPS提升。

## 准备流程

1. 手机入口立即取得互斥令牌，停止触控、清理旧输入并显示独立覆盖层；等浏览器确实有绘制机会后才继续。
2. 淡出旧场景，完成世界/阵容创建。角色逐个准备全部LOD、普通/抖动材质、武器和实际缓冲首用。
3. Boss模式继续准备Boss模型、登场特效、危险区模板、小怪及其爆墨实例缓冲、登场音效和标题字体。准备过程不推进Boss战斗或发送演出事件。
4. 准备实际后处理Pass，执行零时间的完整首帧检查；出现新着色器失败、图形安全停止或上下文丢失时进入明确错误界面。
5. WebGL2通过`fenceSync`、`flush`和零超时`clientWaitSync`轮询确认已提交GPU工作完成。等待时让出浏览器，不调用`gl.finish()`；取消、上下文丢失、失败或超时均释放同步点。
6. 所有准备和首帧确认完成后才显示100%；再等待可见帧与淡入结束，才允许单机开场或联机就绪。Boss开场动画自身有正常演出时长，不将动画时长统称为卡顿。

## 缓存、首绘和资源恢复

- 缓存依据实际renderer和program对象，不依据材质名字推测。材质自身仍须初始化；新增程序要检查接口，着色器检查保持开启。
- 预备绘制使用相同格式的小渲染目标和独立代理，共享实际几何、骨架、实例属性等资源；小目标只用于加载准备，不改变游戏内2倍分辨率。
- 每次隔离绘制恢复渲染目标、viewport、scissor及阴影状态。几何释放后对应首用状态失效；异常或取消不能留下临时挂点与修改后的可见性。
- Boss演出准备恢复粒子数组、实例数量、drawRange和随机状态；小怪模型/特效池在实战借还，取消或失败时安全释放，不通过减少对局人数换取帧率。
- 小怪池预建12份资源，为原有存活上限和1.2秒死亡演出与下一波重叠留出余量；保留原刷怪规则、队伍人数和死亡表现。
- 后续实战首次出现的条带、墨迹、近景角色附件和屏幕效果也必须纳入真实浏览器首用核对。验证不能仅检查开场结束，遗漏效果仍可能在实战首次触发时增加程序。

## 取消、失败和前后台

- 同一手机同时只允许一个准备请求；单机和联机入口共享互斥，淡出/世界准备/资源准备后都检查令牌身份。
- 离房时即使没有显式取消令牌，网络match身份变化也必须使旧准备失效，防止迟到回调重新绑定旧对局。
- 取消后等待正在执行的阶段退出，才恢复菜单演示世界。覆盖层保留到菜单恢复，不能先打开旧世界或提前接受第二次开局。
- 失败保留错误界面并停止普通游戏循环，允许安全返回菜单；可重试的单机请求先清理旧任务和错误锁，再开始新的准备。
- 准备中或错误状态进入后台后，前台明确继续返回菜单。恢复提示层级120高于准备覆盖层110，触屏和键盘都能操作；不自动复活已退出的联机对局。

本批专项命令：

```powershell
node tools/check-mobile-loading.mjs

node tools/check-mobile-character-warmup.mjs
node tools/check-mobile-boss-preparation.mjs

node tools/check-mobile-paint-preparation.mjs
node tools/check-mobile-profiler.mjs

```

上述命令分别覆盖真实Edge界面、主控/诊断/GPU同步点确定性边界、角色缓存及首绘、Boss特效和资源恢复。GPU完成失败、取消和超时的确定性用例使用可控WebGL状态，不能称为手机GPU验收。

完整网页/实战入口验证另运行：

```powershell
node tools/check-mobile-boss-gameplay.mjs
npm run check:mobile
node tools/check-diagnostics.mjs
node tools/check-mobile-gpu.mjs
```

`check-mobile-boss-gameplay.mjs`检查可见/单调进度、100%门槛、真实开场、短时战斗及两轮小怪复用；如果观察到准备后新增程序，应保留失败并定位对应首次使用，不能改成只看开场或忽略新程序。浏览器软件渲染用于行为回归，**不使用其FPS宣称手机稳定帧率**。

本批最终检查：角色/战斗/墨迹/Boss/进度UI/主控/fence/联机/尖峰统计专项均通过；Boss专项另在真实Edge验证标题DOM复用及子动画冒泡。真实成品浏览器先发现并修复了ScreenFX、拳套材质、射击条带、刀光及墨迹首用遗漏；之后默认武器和本地伞武器均通过开场、短时战斗及两轮小怪生成/死亡/复用无新program对象检查。程序监控在开局前安装，以mobile-preparation-ready事件作基线，覆盖最早intro帧，不能把已发生的首帧编译收进基线。

触控、多指、后台恢复、布局、短局结算、PC入口、日志导出上传及跨重启留存通过，页面/资源错误为0。256/224组GPU预算、固定2倍/SMAA真实像素、故障降级/安全暂停通过；PC高画质/物理材质通过，本机无旧GLSL基线，未作逐字节对比。

新增日志：profile.slowFrames保存最近20条≥100ms CPU帧及九段归因，slowFrameCount累计，intervalSpikes保存最近40条≥100ms真实帧间隔，maxIntervalMs记录最大值；这些包含本机提交与等待，不是GPU完成耗时。模式context从实际G.mode和Boss/区域/涂地规则生成。

仍未覆盖：所有地图/武器/副武器/大招组合、完整多端弱网和长时热机；程序稳定检查不是所有动态计算或GPU负载的上限证明。真机待用户安装验证首次开局、Boss开场、射击/近身/受击、小怪生成死亡、后台取消及至少2～3分钟连续实战，不能提前宣称稳定30帧或不再有个位数掉帧。
