# v1.0.12 USB日志传输

手机原生上传优先探测127.0.0.1:18765/api/usb，确认服务标识及协议后，POST到同端口/api/logs。电脑以adb reverse把18765映射到接收器8765，日志固定写入当前仓库releases/logs；本机为J:\DemoInk\releases\logs。无需同一Wi-Fi，亦不需要在APK内配置电脑IP。

## 使用

1. 手机连接数据线、开启USB调试并授权。
2. 仓库根目录执行`./tools/start-usb-debug.ps1`；多设备可用`-Serial`，非默认SDK位置用`-AdbPath`。脚本只创建对应端口映射，启动缺失的接收服务，不覆盖其他端口或关闭无关服务。
3. 手机点击原“上传日志”，成功显示“上传成功（USB）”及相对保存路径。
4. 断线重连、手机/电脑重启或换电脑后重新运行脚本；仅插线不保证adb reverse已配置。关闭通道可用`adb -s 设备序列号 reverse --remove tcp:18765`。

USB握手不可用时才尝试构建时指定的局域网地址；未配置地址时明确报错。已开始POST后不自动改通道重试，以免回执丢失造成重复保存。导出日志仍可单独使用。Android仅额外允许127.0.0.1明文连接，其他明文目标保持原限制，PC网页上传不改变。

## 验证（2026-10-26）

- 接收器真实HTTP测试通过：握手、有效日志落盘、无效格式/来源/大小拒绝。
- Android原生构建通过；连接的ALP-AN00手机已安装测试构建。
- 真实WebView点击上传，电脑得到1份有效code12 JSON，界面确认USB成功。
- 删除USB映射再次点击：正确失败，目录无新增日志；恢复映射后重试成功。
- 本轮测试APK未配置局域网地址，因此成功传输确实经USB；未假定局域网原生分支经过真机验证。
- 测试工具`tools/check-usb-upload.mjs`使用9223上的本机转发WebView调试端口，需先将该端口forward到当前应用的webview_devtools_remote_PID；连接/ADB路径可用ANDROID_SERIAL、ADB_PATH指定。工具会主动上传两次并验证一次断路失败。

新增用户目标：在已授权手机上自动完成Boss模式性能优化闭环，固定2倍高清、以持续30帧为验收目标；USB上传为该闭环的第一项基础设施，不代表Boss性能已达标。
