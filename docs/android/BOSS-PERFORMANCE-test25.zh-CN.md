# v25：手机Boss高频反馈重启避免同步布局

## 依据

v24带方法探针的一分钟调查中附加30秒V8 CPU采样（战斗5秒后开始）。本地boss-cpu-2026-10-26T10-38-05-586Z.json记录约30846.5ms样本；restartAnim三个调用栈的自耗时分别474.2/113.5/104.9ms，HUD._restart另160.3ms。_drawInk770.3ms、角色/绘制也有开销；(program)9742.9ms是未归因于JS函数的时间，不能当作GPU硬件耗时。CPU采样和方法探针有干扰，本轮25.591FPS、≥100ms8帧不作正式成绩；USB上传INKWAVE-logs-20261026-103939-786768-53d9c6e2.json后已关闭。

原重启方式是移除CSS类、读取offsetWidth强制布局、加回CSS类。Boss全队命中会频繁重启血条；本地命中还触发准星/伤害字。这使事件处理在动画重启处付出全局样式和布局的同步成本。

## 修改与边界

- 只对手机Boss战中的血条受击/弱点、徽章弱点、伤害数字弹跳、命中刻度/环及准星受击，交替使用两份内容完全相同的CSS关键帧名称，不读取offsetWidth。
- 类名立即加入，同一调用栈（包含一帧内两个物理步）的重复命中在微任务中合并为一次重启，仍在该帧绘制前执行；没有等待两次rAF的可见延迟。多个独立任务在绘制前交替仍可能合并，当前战斗命中由统一帧同步派发，未以此减少模拟/伤害事件。
- 保留动画时长、曲线、颜色、重击/弱点环和血条弱点优先级；没有删除反馈、降低UI刷新率或影响2倍/SMAA/8人/玩法。
- PC及普通对局保留原同步重启路径；手机样式只覆盖明确标记元素。其他低频动画未替换，避免破坏登场/退场/animationend移除契约。
- 关键帧副本有维护成本。修改原关键帧时必须同步副本，并运行专项逐项比较；不能仅以名称类似认为视觉相同。

## 基础验证

本地8490服务运行时执行node tools/check-mobile-boss-animation.mjs。真实Edge检查8份关键帧CSS逐项相同，7组反馈重播到起点、同帧两次调用仅切换一次、时长/曲线及重击环保持，手机Boss offsetWidth读取0；实际BossHud._hp在PC/普通对局各读1次，原路径保持。另运行语法和Boss准备回归。浏览器结果保存在releases/investigation/mobile-boss-animation-browser.json，不代表真机FPS。

## 执行顺序

基础检查后中文commit/push，再干净构建v1.0.25/code25、安装。先带探针CPU采样复核热点，再无探针两轮60秒，固定原画质真实游玩；每轮自然结束、USB核对后关闭，结果独立提交。若只有同步读取减少而整体帧率仍未通过，必须明确未达标，继续分段定位，不进入60阶段。
