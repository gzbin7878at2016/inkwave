# v1.0.9 / test9：手机启动与菜单长停顿第一批修复

## 真机证据与边界

v1.0.8上传日志确认：华为PLA-AL10 / Maleoon920 / WebView114，93%到Ready区间耗时22.581秒，菜单性能采样存在12.592秒空档。后者不是一次连续阻塞时长；旧日志缺少系统ANR堆栈，不能据此确认Android等待框的具体线程原因。

该设备缺少KHR_parallel_shader_compile；所用Three.js的compileAsync仍先同步调用compile，缺少扩展时不能确认首次使用不会阻塞。代码还在首次完整帧预热隐藏展台，菜单显示2.5秒后自动构建/编译联机大厅。

## 本批改动

- 仅手机入口关闭隐藏展台自动预热和2.5秒联机大厅自动预载；PC继续原流程。用户主动打开装备/大厅时仍保留原入口，不删除功能。
- 手机保留必要特效池/炸弹替身准备，先执行2次不绘制的动画/LOD初始化（每次让出线程），再把真正将显示的网格纳入预热。后处理按Pass分别预热，世界按每批1个可绘制对象真实绘制。每批恢复可见性、裁剪及渲染目标，再requestAnimationFrame让出线程；离屏替身仅在加载覆盖期间临时忽略裁剪。
- 避免只调用compileAsync却把真正首次链接挤到最后几帧。手机收尾只执行1次完整帧，PC仍为原3帧。
- 不改2倍高清、SMAA、60帧目标、对局人数、模拟和命中判定。单个驱动/材质调用仍不可中断；分批不保证每个设备都无长任务，也不保证启动总时长缩短。

## 新日志字段

- `current.startup.checkpoints`：模块导入、boot设置、各进度里程碑，含上一阶段及其耗时；不把里程碑百分比冒充实测进度。
- `current.startup.stages`：特效池、每个后处理Pass、各首次绘制批次（含对象名称）、完整收尾帧；最多256条。
- `current.startup.completedAtMs`：从诊断安装到可交互的耗时。阶段计时含等待/调度，不等同纯CPU耗时。
- `current.responsiveness.longTasks`：Long Tasks API记录的≥200ms长任务，最近60条及全运行计数/最大值；不支持API时明确标记false。
- `current.responsiveness.stalls`：250ms前台心跳的≥750ms额外延迟，最近40条/最大值；后台和恢复间隙排除。这是前台定时器响应延迟，不能当作系统ANR证明。
- `current.responsiveness.operations`：菜单切换、按需大厅构建/编译等最近40个操作耗时；与启动数据分别保存。
- 旧日志导出/上传及上一运行留存保持不变。新字段也有固定条数上限；日志在用户点击后才上传。

## 验证与交付记录

- `node tools/check-mobile-startup.mjs`：逐批覆盖、批次之间让出线程，恢复可见性/裁剪/后处理渲染目标，以及渲染异常后恢复通过。
- `node tools/check-diagnostics.mjs`：验证手机无后台自动大厅/展台、启动分段和仅1次收尾帧；人为制造1.2秒阻塞，验证长任务/心跳响应记录；同时回归GLSL错误、导出、上传成功/失败及跨重启留存。
- `npm run check:mobile`：触控、多指、后台恢复、布局、结算和桌面原入口；结果与构建记录在本机releases，软件渲染不代表手机帧率。
- `node tools/check-mobile-gpu.mjs`：256/224组资源上限、SMAA真实像素、固定高清、墨迹显示、AA/地面失败降级和安全暂停通过。资源预算测试显式预编译地面/格栅，不再依赖生产启动全量编译不可见网格；PC高画质/物理材质检查通过，本机无原GLSL基线，未执行逐字节对比。
- 新APK为versionCode9 / versionName1.0.9，沿用本机test7/test8签名，打包后固定下载页自动更新。源码提交、是否干净、SHA-256及签名/资源检查以本次实际产物记录为准，APK和原始用户日志不入库。
- 真机尚待安装对比。本批不宣称ANR已经消失，不宣称稳定60帧达成。
