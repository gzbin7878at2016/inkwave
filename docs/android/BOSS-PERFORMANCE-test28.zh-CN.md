# Boss性能第28批：扩展手机短音缓存

本批只作用于Android手机Boss实战，PC、普通对局保留原程序化音效；2倍高清、SMAA、8人、伤害、AI、完整音乐和空间音效不变。稳定30帧仍未通过，60帧尚未开始。

## 修改依据与范围

v27原生20秒调查显示AudioOutputDevice实际运行13.309秒，不能把模拟墙钟长停顿全部当成JS计算。单停音乐、切声像未证明稳定收益；挂起完整音频后29.569FPS但p95仍49.9ms，且伴随合成线程变化，不能证明音效是唯一瓶颈，也不能静音交付。

已有3个短音缓存本批扩展到14个：原roller_flick/splat_small/shoot_shooter，加step_ink/step_dry/step_enemy、squid_in/squid_out、jump/land、boss_step、shoot_blaster/blaster_pump/blaster_boom。它们为无状态、1秒内结束配方，局内反复使用；hit_marker连击状态、循环、长音与参数化配方不加入。

仍在Boss加载遮罩内逐项离线合成，每种4份随机变体，实战一个BufferSource代替多振荡器/滤波图，之后仍走原空间定位、音量、距离滤波、混响和并发/节流。采样率跟随真实上下文；总上限8MiB、单份2秒超时，失败/取消回退原配方，不在实战重烘焙。沿用v24边界：变体有限，整体变调也会缩放包络时长，听感需人工验收，不宣称与无限随机音色完全相同。

## 提交前基础验证

`node tools/check-boss-audio-cache.mjs`在真实浏览器OfflineAudioContext检查14种原配方与样本PCM，最大误差1.20e-7；每种4变体均非空、有限且不同。48kHz缓存4,893,904字节，约4.67MiB（原1.36MiB）。逐个验证Boss命中时5节点/1音源、PC/非Boss回退、原空间/混响、参数回退、自然结束释放；取消/异常回退通过。

`node tools/check-mobile-boss-preparation.mjs`检查原Boss/小怪/危险区/标题准备、进度、取消/异常和状态恢复。随后运行通用语法检查。以上不是手机FPS成绩。

## 真机执行与验收

1. 基础检查通过后中文提交并推送用户fork，核对远端HEAD。
2. 从干净提交运行`./tools/build-android.ps1`，记录v1.0.28/code28、源码/哈希/签名、资产一致性；ADB覆盖安装。
3. 一局60秒带方法探针正常游玩，所有ablation环境变量清零，确认14项准备/无失败、命中节点和实际动作；上传USB文件核对源码再关闭。该轮不计成绩。
4. 至少两局独立60秒无探针，所有ablation和testWeapon清零，保持2倍/SMAA/8人。每局自然结束、上传核对、关闭，记录温度、平均/p95/p99/≥100ms。没有证据不得宣称稳30。
5. 结果另行中文提交；若收益不足继续独立定位音频/原生合成，不降低画质、不修改其他场景。长期稳定门槛不因短局方便而放宽。

真机结果待本次干净提交构建后填写；不得将v27静音调查填作v28正式成绩。
