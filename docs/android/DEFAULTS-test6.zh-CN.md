# 测试版6：默认60帧目标与固定2倍高清

## 最新真机日志结论

用户日志 `INKWAVE-logs-20261021-150522-438.json` 对应测试版5，设置确实为 `fpsCap=60 / mobileVisual=hd`，没有shader编译失败或材质降级。模糊的明确原因是自动降分辨率：

| 日志时间（北京时间） | 选择 | 实际密度 | 像素尺寸 |
| --- | --- | --- | --- |
| 15:04:49 | 高清/60帧 | 1.75 | 1347×658 |
| 15:04:54 | 高清/60帧 | 1.25 | 962×470 |
| 15:04:59起 | 高清/60帧 | 1.0 | 770×376 |

该手机窗口770×376，DPR3.5；2倍密度应约1540×752，但当时scale最终降到0.5，因此虽选高清仍以1倍输出，再放大到屏幕。图片中的人物/椅子与3D轮廓发糊符合这个现象。日志不是材质丢失或SMAA降级。设置60帧是目标上限，不代表设备能稳定达到；最后几个采样仍有41～60帧波动。

## 本次行为

1. 手机首次启动默认60帧目标、2倍高清，SMAA路径继续保留；几何档保持low，不连带打开阴影/实时AO等成本。
2. 升级旧APK时一次性迁移 `fpsCap=60 / mobileVisual=hd / mobileDynamicResolution=false`，写入 `mobileDefaultsVersion=1`；保留灵敏度、左右手、音量等无关设置。
3. 迁移后玩家仍可改回其他档位；下一次启动不再强制覆盖手动选择。PC不执行这项迁移。
4. “触控设置”新增“自动降低清晰度”，默认不勾选；关闭时游戏不会因追帧自动降低渲染密度。由勾选改为关闭时立即恢复当前档位的完整密度。
5. 勾选后沿用原自动降分辨率，允许掉帧时自保；手机GPU编译降级/安全暂停仍保留，不等同于分辨率自适应。
6. 日志增加 `basePixelRatio` 与 `resolutionPolicy=fixed/adaptive`，同时记录设置开关、实际pixelRatio、canvas/target，便于核对“选择值”和“实际值”。

2倍密度仍受设备DPR上限约束，不等于原生物理分辨率或固定1080p。固定高清可能降低实际帧率并增加发热，需真机对照；没有承诺2倍高清与稳定60帧同时满足。若卡顿，玩家可主动开启自动降低清晰度或切省电。
