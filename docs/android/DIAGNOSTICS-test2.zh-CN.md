# Android 测试版2：墨迹/场景缺失诊断日志

本版只增加诊断，不改变地面材质、墨迹算法、默认画质或手机GPU兼容策略。版本为 `1.1.0-android-test.2-logs`，versionCode 2，可使用同一debug证书覆盖安装测试版1。

## 手机上怎么操作

1. 安装本次交付的 `INKWAVE-android-test2-<提交号>.apk`，选择覆盖安装。不要先卸载，保留原有设置和复现条件。
2. 启动游戏，进入录像里出问题的练习地图。先不要更改画质；移动、转向、朝地面开火10～20秒，让“地面消失/无墨迹”问题再次出现。
3. 点击左上方 **“导出日志”**。该按钮从启动时即存在，即使加载失败也可点击。
4. 屏幕提示保存成功后，打开手机文件管理器的 **下载 → INKWAVE**，找到最新的 `INKWAVE-logs-日期-时间.json`，把这个文件发回来。默认不需要额外的存储权限，不会自动上传日志。
5. 文件没找到时，按屏幕显示的完整文件名搜索。若提示保存失败，点击“复制报告”，把报告粘贴到文本文件发送也可以。
6. 若刚才强退过，重新启动后立即导出；报告会带上上一次运行的留存错误。为避免覆盖有用证据，复现后先导出再反复重启。

## 日志包含什么

- 当前APK版本、构建源码提交和是否带未提交源码；用户设备型号、Android版本、真实WebView包及版本。
- GPU/WebGL渲染器、驱动公开的上限：片元uniform、varying、纹理大小/层数/单元、顶点属性、浮点精度与扩展。
- 首次着色器编译检查：program链接结果、顶点/片元编译原始错误，前两个失败程序保留有长度上限的GLSL源码。由此判断地面shader是否超限或触发驱动编译问题。
- JavaScript异常、未处理Promise错误、console警告/错误、资源加载失败、fetch错误HTTP状态、WebGL错误码和图形上下文丢失。
- 地图、对局状态、几何顶点数量、地面材质与墨迹纹理引用、图集分配缺失、贴图宽高/数组层数、CPU墨迹计数/覆盖率、性能样本。
- 导出时额外读取最多8个CPU判为有墨的GPU图集像素，用来区分“墨没写进图集”和“图集有墨但地面没显示”。单个透明边缘像素不直接判故障。

## 性能与留存边界

诊断版开启了原版默认关闭的着色器首次编译检查，会增加加载/首次使用时的等待；不要拿本包的首帧卡顿当正式性能结论。没有新增逐帧GPU读回：像素读取只在用户导出时发生；GPU错误/场景状态每约5秒采集。

最多保留160条合并事件、8个shader失败摘要、前2个失败程序源码（每段最多180000字符），导出最多600个已有性能样本。仅在本机保存当前运行及上一运行的有限日志；存储空间不足不会阻止游戏启动，内存报告仍可导出。

文件可能包含设备型号与图形驱动信息，按需发给排查人员；不采集系统账户、通讯录、游戏聊天或认证密钥。URL查询中的常见敏感参数会隐藏；资源URL不记录查询字符串。

## 当前排查判断

录像中角色/围栏/出生点仍显示，而大量可涂墨地面、墙体和墨迹一起缺失；分数继续增长，说明仅靠“低画质”无法解释全部现象。优先怀疑复杂地面材质在手机GPU上的编译/链接或绘制失败，具体原因需手机日志确认。

桌面探测发现地面材质的uTL/uTLt/uTLs各50项，另有墨迹涟漪、游泳尾迹、壁画、灯光等数组；桌面测试GPU的MAX_FRAGMENT_UNIFORM_VECTORS为1024，不能代表手机。资源上限风险是调查方向，尚未取得这台手机的编译器日志，不能宣布已确认根因或已修复画面。

自动验证入口：`node tools/check-diagnostics.mjs`（须先构建移动网页并启动8490静态服务）。测试主动制造仅用于测试的GLSL错误，验证错误/源码捕获、文件导出解析、资源HTTP错误、跨重启留存；测试材质不会打进APK。

Android原生导出已通过编译，手机实际写入Download/INKWAVE仍待用户本次运行验证。不会把浏览器下载测试写成安卓真机导出验证。

实现依据：[Android官方共享存储说明](https://developer.android.com/training/data-storage/shared/media)；图形资源约束参考[Khronos WebGL2参考手册](https://www.khronos.org/files/webgl20-reference-guide.pdf)。设备实际能力仍以导出的GPU上限与编译器日志为准。
