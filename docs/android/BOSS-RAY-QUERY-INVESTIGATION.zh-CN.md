# Boss射线宽相调查

## 当前依据与候选范围

v49当前V8聚合raycast自耗约622ms/30秒，尚非主线程全部成本。原Level.queryBlocks遍历射线XZ包围矩形内所有格子；候选逐z网格行保守计算射线经过的x范围，格子少于12仍回原查询，地图外射线按边缘clamp语义处理。

候选只改宽相列表，继续调用原Physics.raycast的完整slab计算、包含原点忽略、格栅规则、距离/法线/face/UV输出。按照原矩形查询最早出现的格子和块id排序，保留原“等距离后者覆盖”命中顺序。1e-9相对尺度保守边界仅可增加宽相候选，不改精确求交阈值；空间哈希身份/长度不符或输入极端则回原查询。不改产品。

## Node实际Level/Physics预检

check-boss-ray-query.mjs：合成162旋转/重合/格栅/非solid盒、真实tidewater359基础碰撞块，各5226射线（随机、零水平分量、近零分量、网格线、地图外clamp、等距）逐字段命中结果一致，包含沿用out的无命中与无face字段。

Node合成场景候选平均10.0825ms/5226次、原9.3095ms，反而更慢；基础tidewater候选约5.9971ms、原9.3730ms，但尚无布景额外碰撞盒、真实玩家射线分布和手机硬件，不能宣称提帧。控制数组20字节/块。

## 手机实验执行方式（尚未验证）

先node tools/check-boss-ray-query-browser.mjs，在真实dist-mobile的完整Boss布景碰撞盒上复用同手机核心，3000合成射线逐字段核对及ABBA查询墙钟。桌面数据不作手机结果。

BOSS_RAY_QUERY_BENCHMARK=1只允许METHOD_PROBE=1、60游戏秒独立方法轮，其他副本/遮蔽/音频旁路/比较全部0。真实战斗仍走原Physics，每32次查询采一条输入、最多6000条；自然结算后校验安装sourceCommit与当前干净构建一致，再在冻结状态回放全部真实样本。原/候选Hit全部字段逐值一致才继续8组ABBA计时，15秒预算，finally恢复queryBlocks与冻结状态；结束正常菜单恢复、真实UI USB上传并核对关闭。

必须保持2倍/SMAA/8人/原玩法，PC不动；只有真实手机收益可观且全部命中一致，才考虑Boss条件下的产品集成。本轮工具不需要重建APK。
