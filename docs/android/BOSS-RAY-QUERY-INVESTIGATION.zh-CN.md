# Boss射线宽相调查

## 当前依据与候选范围

v49当前V8聚合raycast自耗约622ms/30秒，尚非主线程全部成本。原Level.queryBlocks遍历射线XZ包围矩形内所有格子；候选逐z网格行保守计算射线经过的x范围，格子少于12仍回原查询，地图外射线按边缘clamp语义处理。

候选只改宽相列表，继续调用原Physics.raycast的完整slab计算、包含原点忽略、格栅规则、距离/法线/face/UV输出。按照原矩形查询最早出现的格子和块id排序，保留原“等距离后者覆盖”命中顺序。1e-9相对尺度保守边界仅可增加宽相候选，不改精确求交阈值；空间哈希身份/长度不符或输入极端则回原查询。不改产品。

## 手机实验执行方式（尚未验证）

先node tools/check-boss-ray-query-browser.mjs，在真实dist-mobile的完整Boss布景碰撞盒上复用同手机核心，3000合成射线逐字段核对及ABBA查询墙钟。桌面数据不作手机结果。

必须保持2倍/SMAA/8人/原玩法，PC不动；只有真实手机收益可观且全部命中一致，才考虑Boss条件下的产品集成。本轮工具不需要重建APK。

真实dist-mobile加载Boss后781个碰撞块（含布景），3000条合成射线的Hit全部字段逐值一致，无页面异常。宽相候选189748→44968，访问格117235→34050；1522条小矩形按设计回原路径，不是错误回退。8组ABBA原4组总47.4ms/12000次=0.00395ms每次，候选24.0ms/12000=0.002ms每次，单次差约0.00195ms。仍是桌面合成输入，不能推断手机提帧或实战射线分布。已开始现有v49上的真实一分钟方法采集，结算后复用同核心回放，尚无手机结论。

## 缓存范围收窄至四格

完整布景桌面同核心3000条合成输入的候选列表长度及Hit全部一致，但未限制范围的缓存原平均9.125ms/3000、候选9.975ms，存在负收益。结合真实6000输入：5202单格、471两格、41三格、185四格，超过四格仅101条。因此候选只缓存二至四格，单格直读，超过四格回原查询，避免低复用大矩形的复制和淘汰。

修改后Node合成/基础/6000实战全部命中一致、失效/预算通过；实战显式缓存7176字节、137项；ABBA原约3.3496→候选2.83785ms/6000。合成基本持平/基础tidewater约慢6%，仍保留负结果。手机尚未实测，不当实战提帧。
